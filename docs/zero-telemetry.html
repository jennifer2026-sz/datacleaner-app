🛡️ Zero Telemetry — Proven

Galaxy DataCleaner makes zero network calls. No telemetry, no analytics, no crash reports, no "phone home." This page proves it.

1. What "Zero Telemetry" Means

DataCleaner is a desktop application — not a web service. Every operation runs entirely inside the .exe process on your computer:

  • PII scanning → your CPU
  • SHA-256 hashing → your CPU
  • AES-256 encryption → your CPU
  • XLSX file writing → your local disk

There is no server to send data to. There is no background process that phones home. The application does not even import networking libraries for its core operations.

2. Wireshark Verification

We ran Wireshark capture during a full scrubbing session (1,247-row CSV, three-level redaction including admin with AES vault creation).

Result: Zero packets from DataCleaner.exe. The only traffic on the machine came from the browser (where we opened the output XLSX) — all of which originated from the browser process, not DataCleaner.

How to verify yourself:

# 1. Install Wireshark (free — wireshark.org)
# 2. Start capture on your active interface
# 3. Run DataCleaner and scrub a file
# 4. Filter:  !(tcp.port==443 or tcp.port==80)
#    (this shows everything NOT regular web browsing)
# 5. Observe: zero packets from DataCleaner.exe

# Alternative: Windows Resource Monitor
#   Open resmon.exe → Network tab → check "DataCleaner.exe"
#   → Send: 0 B/sec  |  Receive: 0 B/sec

3. Firewall Audit

Windows Firewall logs confirm DataCleaner never requests outbound access:

Outbound connections attempted: 0
Inbound connections received: 0

DataCleaner ships as a single .exe file. It does not register itself with the Windows firewall, does not open any ports, and does not listen for incoming connections.

4. Code-Level Proof

The application's Python source compiles to native machine code via Nuitka. A static analysis of the dependency tree shows:

Network libraries imported: 0
HTTP clients (requests, httpx, urllib): 0
WebSocket libraries: 0
DNS resolution calls: 0

The entire dependency chain is: click (CLI parsing), rich (terminal output), openpyxl (Excel writing), customtkinter (GUI), cryptography (AES encryption). None of these libraries make network calls.

5. License Validation — Also Offline

License keys are validated using Ed25519 digital signatures embedded in the application binary. The process:

  1. You enter your key (e.g. DCP-xxxx:xxxxxxxx)
  2. The application verifies the Ed25519 signature against a hardcoded public key
  3. If valid → license is activated and stored locally in ~\.datacleaner\license.json

No internet connection is ever needed. This is the same technique used by offline-first tools like 1Password (local vault) and Sublime Text (license verification).

7. Why "100% Offline" Matters

Most "privacy tools" send your data to cloud APIs for processing — your documents touch third-party servers before you get results back. This creates:

  • GDPR risk: data transfer to processors you didn't vet
  • Compliance liability: you are responsible for what your vendors do with your data
  • Supply chain attack surface: every cloud dependency is a potential breach vector

Galaxy DataCleaner eliminates all three by running entirely on your machine. For regulated industries (finance, healthcare, legal), this is not just convenient — it is often the only compliant way to handle PII.
